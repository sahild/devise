# Devise on Amazon DynamoDB: sample application

A minimal Rails 8.1 application that authenticates users stored in Amazon
DynamoDB with Devise. It uses the Devise checked out in this repository
(`gem "devise", path: "../.."`) and enables the seven modules supported on
DynamoDB, plus `:registerable` for sign up:

`database_authenticatable`, `rememberable`, `validatable`, `confirmable`,
`trackable`, `recoverable`, `lockable`

The app can run on either library Devise supports:

| `DYNAMODB_LIBRARY` | Model | Table |
| --- | --- | --- |
| `dynamoid` (default) | [app/models/user.rb](app/models/user.rb) | `devise_example_dynamoid_<env>_users` |
| `aws_record` | [app/models_aws_record/user.rb](app/models_aws_record/user.rb) | `devise_example_aws_record_<env>_users` |

## Running it

Requirements: Ruby 3.2+, and DynamoDB Local (or another DynamoDB endpoint).

```console
# 1. Start DynamoDB Local
docker run -d -p 8000:8000 amazon/dynamodb-local

# 2. Install gems
bundle install

# 3. Create the users table
bin/rails devise:dynamodb:create

# 4. Start the app
bin/rails server
```

Open http://localhost:3000. To use aws-record, set `DYNAMODB_LIBRARY=aws_record`
for every command, e.g. `DYNAMODB_LIBRARY=aws_record bin/rails devise:dynamodb:create`.

To point at another endpoint, set `DYNAMODB_ENDPOINT`. In production the
endpoint is left unset and the standard AWS credential chain is used.

### Emails

In development, Devise's emails (confirmation, password reset, unlock) are not
sent; they are written to `log/development.log`. Copy the links from there to
confirm an account, reset a password or unlock an account.

## Things to try

1. Sign up. Signing in fails until you open the confirmation link from the log.
2. Sign up again with the same email: "Email has already been taken".
3. Sign in with "Remember me", then visit `/account` to see the trackable fields.
4. Sign out and try the wrong password 20 times: the account is locked and an
   unlock link is written to the log.
5. Use "Forgot your password?" and follow the reset link from the log.

## Where the DynamoDB setup lives

| File | Purpose |
| --- | --- |
| `Gemfile` | `devise` plus `dynamoid` and `aws-record` (a real app needs only one). |
| `config/initializers/devise.rb` | `config.dynamodb_library` and `require 'devise/orm/dynamodb'`, generated by `rails g devise:install --orm=dynamodb`. |
| `config/initializers/dynamodb.rb` | Endpoint, region, credentials and the Dynamoid namespace. |
| `config/application.rb` | `config.generators.orm :dynamodb`, and loading the right `User` model for `DYNAMODB_LIBRARY`. |
| `app/models/user.rb` | Dynamoid model, generated by `rails g devise User` with all modules' fields enabled. |
| `app/models_aws_record/user.rb` | The same model with aws-record. |

Other useful tasks:

```console
bin/rails devise:dynamodb:status   # tables, whether they exist, and their indexes
bin/rails devise:dynamodb:drop     # drop the tables
```

See the "Amazon DynamoDB" section of Devise's README for the full
documentation, including the behaviours that differ from Active Record.
